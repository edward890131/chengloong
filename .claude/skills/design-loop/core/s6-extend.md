# S6 · 依 Guideline 延伸新頁

目標：新畫面看起來是既有系統的一部分，而且樣式數量不失控。

輸入：wireframe 或需求、Guideline（尤其頁面樣板章與 AI 延展章）、`manifest.benchmarks`（業主認可的基準頁）。

## 0. 動工前

- 沒有 git 的專案：把這批會動到的 CSS／HTML 複製到 `_design-loop/backup/<日期>_before_s6/`，S7 R1 比「新增」用。有 git 就記下目前 commit。
- S6 是循環，不改 `manifest.stage`；接下來跑 S2–S4 時也不改（那幾站的「過站」只用在首次建置）。

## 1. 拆解

- wireframe → 區塊清單 → 每個區塊對到手冊的樣板或元件，寫成表：`區塊｜wireframe 欄位｜對應元件／變體｜判斷樹層級`。
- **wireframe 上有的欄位＝已經決定，照做不用問。** 不能自己加 wireframe 以外的欄位（例：自己補分類標籤、閱讀時間、檔案格式）。
- 新頁要不要加進導覽、放在哪個入口：wireframe 或需求有寫就照做，沒寫就問。
- 每個新畫面給畫面代碼、歸到功能 page，`wireframe_ref` 記 wireframe 位置（網址只記連結）：照 `core/figma-pages.md` §2–§4。
- 設計師指定把自己畫的畫面加進正式區：當成沒有 wireframe 的新頁，照 `core/figma-pages.md` §4 跑完整流程，原稿只當參考。

### wireframe 更新（已有設計的頁面改版）

業主給「更新後的 wireframe」時，是**更新，不是重新設計**：

- **wireframe 只當參考架構**：用來看最終的結構異動（區塊增刪、順序、欄位、文案、流程、狀態）。wireframe 的畫法（灰底泡泡、灰按鈕、線框排版、某個區塊的擺法）不是設計指示。
- **主要 UI 產出依據是 Guideline 既有元件與 key page。** 每個區塊先找既有元件與 key page 的原樣式照用，只把 wireframe 的結構異動套上去（改文案、增減欄位、加缺的狀態）。
- **只有既有元件做不到的結構，才走判斷樹 ③ 以後。** 不因為 wireframe 畫得不一樣就長新變體或新元件：「wireframe 長這樣」不是新增理由。新增前在拆解表寫出「既有元件哪一點做不到」。
- 拆解表多一欄：`區塊｜wireframe 結構異動｜沿用的既有元件（key page 節點）｜只改什麼｜判斷樹`。
- 既有元件的樣式與互動（例：推出式側欄、帶 icon 的選單、商品卡版型）不跟著 wireframe 改；wireframe 和既有樣式衝突、又分不清是結構異動還是畫法時，先問使用者。

## 2. 收斂判斷樹（每個區塊都走一次）

```
① 既有元件直接用
② 既有元件換變體或屬性值
③ 母版加變體／BOOLEAN／INSTANCE_SWAP（向下相容：不動既有 key、屬性名、預設值）
④ 用既有 token、既有子元件、既有視覺語彙組新元件
⑤ 新增 token
⑥ 新增元件類別或新的風格語彙
```

- 從 ① 開始，前一層能解決就停。
- **④ 和 ⑥ 的分界**：④ 的新元件只用手冊裡已經有的字級、色、線條、圓角、間距與子元件組成（例：用既有 H5、hairline、圓點、間距做時間軸）；⑥ 會帶進手冊沒有的形狀、版型類別或動態類型（例：斜切卡片、瀑布流、視差）。
- ①–④ 自主做。
- ⑤⑥ 可以自主做，但要在 REVIEW_LOG 的「新增理由」寫：需求是什麼、最接近的既有選項是哪個、為什麼不行。
- **一定要停下來問**：wireframe 以外的內容欄位、導覽或資訊架構變更（wireframe 沒寫的）、改全站既有 token 的值、新增一整類 token（第二套字體、新的品牌色系）。
- 同一頁新增 token 超過 3 個：先停下自查是不是在發明新風格，把清單列給使用者。
- 母版權限：單一 agent 作業時自己就是母版負責人，照 S3 規則改；多 agent 分工時照 S4「頁面 agent 不改母版」。

## 3. 做 HTML

- 載 tokens.css＋components.css；會重複用的新樣式寫進 components.css（`.{prefix}-*`），只屬於這頁的才寫頁面 CSS。
- 新元件同時補手冊元件章（Ant Design 格式），新樣板補頁面樣板章，手冊版本號加一。
- 視覺與動態語彙對齊 benchmarks：同類區塊的節奏、字級層級、捲動行為和基準頁一致。

## 4. 回到 Figma

S2 擷取 → S3 補新母版／變體（更新 registry）→ S4 重建 → S7 復盤。每一步照該站驗收；過程中的三邊異動照 S5 記錄。

## 回報格式（每頁）

- 新增：token N 個、元件 N 個、變體／屬性 N 個（逐項列名稱與判斷樹層級）
- 沿用：元件 N 個
- 待使用者決定：清單，或「無」
